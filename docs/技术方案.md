## 1. 框架

Phaser 3 + TypeScript + Vite。不用 Godot。

## 2. 操作

两端用同一套规则：**想干什么就点那个东西**。

- 只有一件事可做时直接执行；有多件事时弹出小菜单。
- 目标太远时自动寻路走过去再执行。
- **iPhone**（横屏）：左半屏浮动摇杆走路；轻点目标物来操作；右下角放「使用」按钮（对面前一格），另有背包、菜单按钮；底部是工具栏。竖屏时提示横过来。
- **Mac 鼠标**：和手机一样点。
- **Mac 键盘**（全程可以不用鼠标）：WASD 或方向键走路；空格 = 用手上的工具；回车 = 交互/确认；小菜单用方向键加回车，Esc 取消；Q = 背包；数字键 1~9 换工具；M = 菜单。
- 所有键位、摇杆大小、透明度都写在 `src/config/settings.ts`，可以改。

## 3. 离线、发布、转 app

- 做成 PWA（vite-plugin-pwa）：可以添加到主屏幕，离线也能玩，联网后自动更新。
- **发布用 Cloudflare Pages**，不用 GitHub Pages。仓库是私有的，免费账号的私有仓库用不了 GitHub Pages。网站挂在根路径 `/`。
- 游戏要提醒 iPhone 玩家把它添加到主屏幕，因为只在 Safari 里玩的话，iOS 可能会清掉存档。
- 以后转 app：iOS 用 Capacitor，Mac 用 Tauri，都是套壳，不重写。所以从现在起：
  - 数据和逻辑分开放；
  - 存档读写只走一个入口；
  - 输入统一翻译成「动作」，游戏逻辑不关心玩家用的是什么设备。

## 4. 数据与存档

| 内容 | 格式 | 位置 |
| --- | --- | --- |
| 数值表（作物、物品、打工、修房、时间体力、开局） | `.ts` 数据文件，每项都带中文注释，并有类型检查 | `src/data/` |
| 常调设置（速度、键位、颜色、摇杆） | `.ts` | `src/config/settings.ts` |
| 界面文字 | 语言文件，中文、英文各一份 | `src/locales/` |
| 剧情对话 | ink（用 inkjs 运行） | `src/story/`（以后建） |
| 地图 | 原型阶段用字符画 `.ts`；正式地图用 Tiled JSON | `src/world/` → 以后 `src/maps/` |
| 存档 | 带 `saveVersion` 的 JSON，存在 IndexedDB | 由游戏生成 |

**存档规则**

- 3 个存档位。存档能一键导出成文件、再导入回来。旧版本的存档在加载时自动迁移到新格式。
- **床边菜单**有三项：睡觉（结束这一天，自动存档）、存档（只存档，不睡，接着过今天）、取消。
- 因为可以在白天存档，存档必须完整记下：当前时间、人物位置和朝向、体力、钱、背包、每一格田的状态（含当天是否浇过水）、NPC 的位置和状态、任务、好感度、线索、剧情变量。
- **临时进度**：游戏切到后台或网页被关时，自动存一份，和 3 个存档位分开。下次打开时问玩家要不要从那里继续。

## 5. 代码分块

- **Zeyu 会改的**：`src/config/`、`src/data/`、`src/locales/`、地图、`src/story/`、`public/` 下的素材。
- **程序**：`src/scenes/`（标题、农场、小镇、屋内、界面）、`src/systems/`（时钟、体力、农田、背包、存档、对话、任务、好感度、线索）、`src/input/`（统一输入）、`src/world/`。
- **说明**：`README.md` 里有「想改什么，去哪里改」对照表，每次加了能调的东西就补上；本文件放在 `docs/技术方案.md`。
- 文件夹和文件名用英文。每个文件开头用中文写清楚用途。凡是能调的值，旁边都写中文注释，注明单位。

## 6. 开发顺序

每一步做完，都要能在 iPhone 和 Mac 上打开试玩。

1. 打地基：骨架、发布、PWA、说明文件
2. 能走路：地图、人物、三种操作方式
3. 种田一天：时间体力、开垦、播种、浇水、收获、睡觉、床边存档、临时进度
4. 小镇生活：背包、商店买卖、打工送货、NPC 对话（ink）
5. 修房子：采集材料、房子升级
6. 主线剧情：线索、好感度、剧情事件（等主线剧情稿）
7. 换装打磨：正式美术和音乐、手感、测试

在第 7 步之前，画面用色块和占位图。

## 7. 写代码的通用规矩

- 改动要小步提交，提交说明用中文。
- 不把中文写死在代码里，玩家看到的字一律放进语言文件。
- 新加的数值放进 `src/data/` 或 `settings.ts`，不要写死在逻辑里。
- 每次做完，先确认 `npm run build` 能通过，再推送。
- 每次做完，在 README 里写清楚：现在能玩什么、在哪改什么。
